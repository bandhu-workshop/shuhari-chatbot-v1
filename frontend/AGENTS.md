# frontend

> **Last updated:** 2026-11-26 17:48 IST

React + TypeScript, Vite, Tailwind. `node_modules` lives here. Talks only to the backend API on :8000, under `/api/v1`.

## Layout
```
src/
  features/
    chat/          # message list, composer, streaming renderer, tool-call cards
    sessions/      # sidebar: list, rename, delete, resume
    memory/        # view/edit/delete what the assistant remembers
  components/ui/   # shared presentational components only
  lib/
    api.ts         # fetch + SSE client; the only place that calls the backend
    api-types.ts   # GENERATED by `just types` from the backend OpenAPI schema; never edit by hand
  hooks/
  app.tsx
  main.tsx         # entry point; mounts app.tsx
tests/
  unit/            # vitest, node environment. Mirrors backend/tests/unit/
  e2e/             # Playwright, later
```

## Naming

**kebab-case filenames, PascalCase component names.** The file is lowercase; the thing it
exports is not.

| Kind | File | Export |
| --- | --- | --- |
| Component | `message-list.tsx` | `MessageList` |
| Hook | `use-chat.ts` | `useChat` |
| Plain module | `api.ts`, `api-types.ts` | `camelCase` functions |
| Types / interfaces | wherever they belong | `PascalCase` |
| Folder | `features/chat/`, `components/ui/` | — |

Why kebab-case and not PascalCase files: it avoids collisions on case-insensitive
filesystems, and it keeps one naming rule across the whole repo instead of two. Community
practice is split on this — `eslint-react`'s filename rule defaults to PascalCase and some
style guides want the filename to match the default export — so this is a deliberate
choice, not a universal standard. Don't flip it per-file.

Repo-wide convention: [../AGENTS.md#naming](../AGENTS.md#naming). No date prefixes in
frontend source; those are for dated working documents only.

## Conventions
- oxlint + Prettier + `tsc` clean (CI checks all three). `just fmt` formats.
- **Prettier formats code, not documentation.** `.prettierignore` excludes `*.md`, because
  docs are hand-wrapped and `just docs-audit` owns them, and this is the only `AGENTS.md`
  that sits where prettier runs — formatting it would split it from the others. It also
  excludes `src/lib/api-types.ts`, which `just types` generates.
- **Type-check with `tsc -b`, never `tsc --noEmit`.** `tsconfig.json` is a solution file
  (`"files": []` plus project references), so `tsc --noEmit` exits 0 even when `src/` has
  type errors. Verified: it passed on a deliberately broken file. `-b` builds the
  referenced projects and is what actually checks types.
  oxlint is what `create-vite` scaffolds now and what `npm run lint` runs; config is
  `.oxlintrc.json`. Don't swap in ESLint without a concrete rule oxlint can't express.
- Feature folders own their components, hooks and state; move to `components/ui/` only when 2+ features use it.
- Streaming: render tokens as they arrive; tool calls as collapsible cards; Stop button.
- Markdown + code highlighting for assistant messages.
- React state + context first; no global state library until needed.
- Every user action (send, stop, regenerate, thumbs up/down) maps to one function in `lib/api.ts`.

## Coding style and testing

Repo-wide coding style: [../AGENTS.md#coding-style](../AGENTS.md#coding-style). It applies
here too, TDD included. Development goes through the superpowers skills —
[../AGENTS.md#how-we-work](../AGENTS.md#how-we-work).

- **TDD applies to logic, not to pixels.** Hooks, parsers, the SSE event reader, state
  reducers and everything in `lib/` get a vitest test written first. Presentational
  components don't — a snapshot test of markup is maintenance without signal.
- **Never assert on model output.** Assistant text is non-deterministic. Test that a token
  *renders*; never test *what* it says. Model behaviour is measured in `backend/evals/`.
- Capacity target is 50 concurrent users
  ([ADR 0003](../docs/decisions/0003-capacity-target.md)). Nothing on this side needs tuning
  for it. The one thing that matters here is that the SSE client reconnects and resumes
  rather than restarting the turn.

## Portability (Cloud Run is the deployment target)

Decided in [docs/decisions/0001-deployment-strategy.md](../docs/decisions/0001-deployment-strategy.md).
Local-first development, but these are cheap now and expensive to retrofit.

- **The API base URL comes from `VITE_API_BASE_URL`**, defaulting to `/api/v1`. The backend
  versions its routes; `/healthz` and `/readyz` sit outside the versioned prefix and are
  not called from the app. Locally and under
  `just stack` the backend is same-origin behind nginx; in production the frontend may be served
  from Firebase Hosting or GCS while the backend is a separate Cloud Run service on another
  origin. `lib/api.ts` is the only file that reads it.
- **SSE streams will be cut mid-response.** Cloud Run's request timeout defaults to 5 minutes
  and maxes at 60, and the client then gets a 504. The streaming client reconnects and resumes
  from the session rather than restarting the turn, and the UI shows a reconnecting state rather
  than an error. Build this at milestone 2; it is a protocol change afterwards.
- **`VITE_*` variables are baked into the bundle at build time and are public.** Never put a
  secret, key or internal URL in one.
- **No build-time knowledge of the backend host.** Anything environment-specific is either the
  base URL above or a runtime fetch.
