# frontend

> **Last updated:** 2026-11-26 13:01 IST

React + TypeScript, Vite, Tailwind. `node_modules` lives here. Talks only to the backend API on :8000, under `/api/v1`.

## Layout
```
src/
  features/
    chat/          # message list, composer, streaming renderer, tool-call cards
    sessions/      # sidebar: list, rename, delete, resume
    memory/        # view/edit/delete what the assistant remembers
  components/ui/   # shared presentational components only
  lib/
    api.ts         # fetch + SSE client; the only place that calls the backend
    api-types.ts   # GENERATED by `just types` from the backend OpenAPI schema; never edit by hand
  hooks/
  App.tsx
tests/e2e/         # Playwright, later
```

## Conventions
- ESLint + Prettier + `tsc` clean (CI checks all three). `just fmt` formats.
- Feature folders own their components, hooks and state; move to `components/ui/` only when 2+ features use it.
- Streaming: render tokens as they arrive; tool calls as collapsible cards; Stop button.
- Markdown + code highlighting for assistant messages.
- React state + context first; no global state library until needed.
- Every user action (send, stop, regenerate, thumbs up/down) maps to one function in `lib/api.ts`.

## Portability (Cloud Run is the deployment target)

Decided in [docs/decisions/0001-deployment-strategy.md](../docs/decisions/0001-deployment-strategy.md).
Local-first development, but these are cheap now and expensive to retrofit.

- **The API base URL comes from `VITE_API_BASE_URL`**, defaulting to `/api/v1`. The backend
  versions its routes; `/healthz` and `/readyz` sit outside the versioned prefix and are
  not called from the app. Locally and under
  `just stack` the backend is same-origin behind nginx; in production the frontend may be served
  from Firebase Hosting or GCS while the backend is a separate Cloud Run service on another
  origin. `lib/api.ts` is the only file that reads it.
- **SSE streams will be cut mid-response.** Cloud Run's request timeout defaults to 5 minutes
  and maxes at 60, and the client then gets a 504. The streaming client reconnects and resumes
  from the session rather than restarting the turn, and the UI shows a reconnecting state rather
  than an error. Build this at milestone 2; it is a protocol change afterwards.
- **`VITE_*` variables are baked into the bundle at build time and are public.** Never put a
  secret, key or internal URL in one.
- **No build-time knowledge of the backend host.** Anything environment-specific is either the
  base URL above or a runtime fetch.
